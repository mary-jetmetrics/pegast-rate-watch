# Курс Пегаса

Каждое утро присылает в Telegram курс евро туроператора Pegas Touristik и копит
историю в [`history.csv`](history.csv).

Нужно, чтобы поймать выгодный момент для доплаты остатка за тур на Фукуок
(бронь от 10.07.2026, зафиксирована в евро — значит важен только курс, по которому
пересчитывается каждый платёж).

## Откуда данные

Страница `agency.pegast.ru/ExchangeRates` рисует таблицу через JS, но под ней лежит
открытый эндпоинт, отдающий курс на **любую** дату:

```
POST https://agency.pegast.ru/ExchangeRates/GetExchangeRates
Content-Type: application/json

{"date": "2026-06-15"}
```

Отвечает `{"Rates":[{"SourceCurrency":"EUR","Rate":88.5800, ...}]}`. Авторизация не нужна.

Ответ — не строгий JSON: даты приходят литералом `new Date(1783641600000)`, поэтому
перед разбором его чиним регуляркой.

## Когда Пегас ставит курс

По будням после 17:30 МСК — на следующий день. Часто пятничный курс держится всю
субботу, воскресенье и понедельник (10 июля — 92,44, а 11–13 июля — 93,58), но не
всегда: 24 июля было 95,48, а уже 25–26 июля — 94,89. Если пропустить выходные,
это падение спрячется внутри них, и понедельничное «по сравнению со вчера» его не
покажет. Поэтому шлём каждый день — так любой пересмотр курса виден сразу и в тот
же день попадает в `history.csv`.

Для нас важно, что курс на сегодня готов ещё с вечера и меняться не должен. Гнаться
за минутой публикации не надо, надо лишь успеть до начала рабочего дня турагента —
платим через неё, а она Пегасу.

## Почему запусков четыре, а сообщение одно

У расписаний GitHub Actions нет гарантий по времени. 13.07 утренний запуск опоздал
на 3 часа 18 минут, а поставленный на вечер того же дня не случился вовсе. На одном
кроне «железно к утру» не построишь.

Поэтому крона четыре — 02:37, 04:07, 05:37 и 07:37 по Перми (см. [`daily.yml`](.github/workflows/daily.yml)).
Ночью курс на сегодня давно выставлен, ждать утра незачем. Даже если запуск опоздает
на те же три с лишним часа, первая попытка приземлится около шести утра; чтобы
сообщения не было вовсе, должны пропасть все четыре подряд.

Сообщение при этом одно: отправив его, скрипт пишет дату в `last_sent.txt` и коммитит
файл. Следующие запуски видят отметку и молча выходят. Отметка ставится **после**
успешной отправки — упади мы на Telegram, следующая попытка должна попробовать снова,
а не решить, что за сегодня всё сделано.

Пересмотр курса задним числом от этого не теряется: запуск, который промолчал, ничего
и не перечитывал, а расхождение поймает первый запуск следующего дня и скажет о нём
в сообщении.

## Самый актуальный курс по запросу (`--preview`), только вручную

Пегас выкладывает курс на завтра вечером, после 17:30 МСК (по Перми — около 19:00).
Режим `--preview` — это «покажи самый свежий курс прямо сейчас»: спрашивает завтра,
а если завтрашний ещё не выложен — показывает сегодняшний. **По расписанию не
запускается** — автоматическое сообщение одно, утреннее; этот режим дёргаем руками,
когда вечером хочется заглянуть вперёд.

Логика «завтра, иначе сегодня» опирается на то, что API не умеет отвечать «курса на
эту дату ещё нет» (см. ниже) — на неустановленную дату он молча отдаёт последний
известный. Поэтому:

* курс на завтра **отличается** от сегодняшнего → Пегас уже выложил, шлём его как
  «Курс на завтра»;
* **совпал** → выкладки, скорее всего, ещё нет, шлём актуальный сегодняшний как
  «Курс на сегодня» и честно пишем, что завтрашний не подтверждён.

Так протянутое значение никогда не выдаётся за решение оператора.

**Как запросить сейчас:** Actions → «Курс Пегаса» → Run workflow → галочка
`preview` → Run. Через полминуты курс придёт в чат. Страницу Run workflow удобно
сохранить закладкой на телефоне — тогда это пара тапов.

Автоматический вечерний прогон пробовали и убрали: второе сообщение в день не нужно.

В `history.csv` предварительный курс не пишется: записать протянутое значение
означало бы придумать курс.

## Почему история перечитывается, а не пишется один раз

В волатильные дни оператор оставляет за собой право переставить курс несколько раз
за день, в том числе после того, как мы его записали. Поэтому каждый запуск
перечитывает последние `RECHECK_DAYS` дней поверх сохранённого и, если значение
разошлось, чинит историю и говорит об этом в сообщении.

Само по себе это не выяснить у API: **он не умеет отвечать «курса на эту дату ещё
нет»**. На неустановленную дату он молча отдаёт последний известный курс — на год
вперёд вернёт сегодняшний. Поэтому спрашивать будущие даты бессмысленно, а `None`
из `fetch_rate` означает сбой API, а не отсутствие курса.

## Бот `/завтра` (`bot.py`) — написан, но не запущен

В репозитории лежит `bot.py` — бот, отвечающий на команду `/завтра` самым актуальным
курсом. Логику он не дублирует: зовёт `fetch_rate` и `build_preview_message` из
`rates.py`, так что ответ совпадает с `python3 rates.py --preview`. Умеет два режима:
бесконечный long-polling (по умолчанию) и `--once` — один проход для запуска по крону.

**Сейчас он нигде не запущен, и это осознанно.** Чтобы отвечать на команды из чата,
нужно «слушать» входящие Telegram, а Actions чат не слушает — он просыпается по крону.
Пробовали поллинг через Actions (`bot.py --once` раз в 5 минут): не годится — у
расписаний Actions нет гарантий по времени, на практике ответ приходил через час.
А живой always-on хост требует положить туда токен бота, который сидит в приватном
чате, — от этого отказались.

Поэтому курс по запросу берём вручную через Run workflow (см. выше). `bot.py` оставлен
на случай, если однажды появится доверенный хост: тогда достаточно запустить его там
без `--once`, и `/завтра` начнёт отвечать за секунды.

## Настройка

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Что это |
|---|---|
| `TG_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `TG_CHAT_ID` | ID группы, куда слать (отрицательное число) |

Константы брони — вверху `rates.py`: `BOOKING_DATE`, `BOOKING_RATE`, `TOUR_TOTAL_EUR`.

## Как учитываются платежи

Тур стоит 3 423,60 €. Каждый платёж пересчитывается в евро по курсу того дня,
когда он прошёл, и уменьшает остаток. Список — в `PAYMENTS`:

```python
PAYMENTS = [
    (dt.date(2026, 7, 10), 65_000, 92.44, 703.15),  # дата, ₽, курс, зачтено €
]
```

Зачтённые евро берутся **из учёта туроператора**, а не считаются заново:
он округляет вниз (65 000 / 92,44 = 703,159 €, зачёл 703,15 €), и остаток
должен сходиться с его цифрами.

**Внесли доплату — допишите строку в `PAYMENTS`.** Остаток и итоговая сумма
тура пересчитаются сами.

## Локальный запуск

```sh
python3 rates.py --dry-run             # показать сообщение, не отправлять
python3 rates.py --dry-run --preview   # то же для курса на завтра
python3 rates.py --force               # отправить, даже если за сегодня уже уходило
python3 rates.py                       # отправить (нужны TG_BOT_TOKEN и TG_CHAT_ID)
```

Руками из GitHub: Actions → «Курс Пегаса» → Run workflow. Ручной запуск всегда шлёт
сообщение, отметка `last_sent.txt` ему не помеха; галочка `preview` переключает курс
на сегодня на курс на завтра.

Зависимостей нет, только стандартная библиотека.
